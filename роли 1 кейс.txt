1.Фетисов.
 Frontend-разработчик (SPA, TS/JS + HTML/CSS)
Зона ответственности:

Архитектура SPA без фреймворков: роутинг (hash/history), компонентный подход, состояние (лёгкий store на TS).

Лента постов: карточки, скелетоны загрузки, пагинация/бесконечная прокрутка.

Фильтры (по дате, типу поста, автору) — UI + синхронизация с API.

Механика «реакций-настроений»: согласен / спорно / весело.

Адаптивность, доступность (a11y: фокус, aria-атрибуты).




2.Попов
 Backend-разработчик (Node.js + MySQL)
Зона ответственности:

REST API на Express/Fastify: GET /posts, POST /reaction, GET /filters.

Схема MySQL: posts, reactions, users (mock), индексы под пагинацию и фильтры.

Курсорная пагинация (не OFFSET) — показать middle-уровень.

Валидация входных данных, обработка ошибок, единый формат JSON-ответов.

Rate limiting (простой in-memory) и базовая безопасность (CORS, helmet).


3.Зимин
 Rust-разработчик (микросервис агрегации реакций)
Зона ответственности:

Микросервис на Axum: агрегация счётчиков реакций (по посту и по типу).

Эндпоинт GET /aggregate?post_id=... — возвращает суммарные счётчики.

Взаимодействие с MySQL из Rust (sqlx), либо кэш в памяти (DashMap) + периодический flush в БД.

WebSocket-канал для live-обновления счётчиков (задача со звёздочкой — можно заложить каркас).

Dockerfile для сервиса.


4.Кобелев
 Fullstack / API-интегратор (связка фронт ? бэк ? Rust)
Зона ответственности:

OpenAPI/JSON-контракты между фронтом, Node и Rust-сервисом (единый формат).

Клиентская обёртка над API на TS (типы, сгенерированные/написанные вручную).

Проксирование запросов: фронт ? Node ? Rust (или фронт напрямую к Rust для агрегации).

Обработка состояний загрузки/ошибок на стыке сервисов, retry-логика.

Настройка docker-compose (Node + MySQL + Rust).
