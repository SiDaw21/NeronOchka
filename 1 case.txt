КЕЙС 1. ВКонтакте — «Мини-приложение для сообщества»
Тема: Разработка веб-мини-приложения для сообщества

О чём этот кейс?
ВКонтакте развивает экосистему мини-приложений внутри сообществ. Наша задача — показать, как небольшой сервис может решать повседневные задачи паблика: публиковать посты, собирать реакции, показывать активность. Командам предлагается разработать рабочий прототип мини-приложения для вымышленного сообщества.

Цель
Разработать SPA-мини-приложение, которое позволяет пользователю без регистрации открыть ленту постов сообщества, отфильтровать их, поставить реакцию и увидеть агрегированную статистику. Игрок должен почувствовать себя участником живого сообщества.

Технические требования и задачи
Платформа. Браузерная версия. Доступ без email/телефона. Допускается ввод никнейма перед началом сессии.

Завершённость прототипа. Полноценная лента с пагинацией, фильтрами, карточками постов и реакциями.

Backend. Node.js (Express/Fastify) — REST API: GET /posts, POST /reaction, GET /filters.

БД. MySQL: таблицы posts, reactions, users (mock).

Rust. Отдельный микросервис (Axum) для агрегации счётчиков реакций в реальном времени.

Frontend. HTML/CSS/TS без тяжёлых фреймворков — компонентный подход, скелетоны загрузки.

JSON. Формат ответов API, конфиги фильтров.

Тестирование. Нет критических багов; пагинация не ломается при пустых данных.

Масштабируемость. Архитектура должна позволять добавить комментарии и вложения без переписывания ядра.

Уникальность. Своя механика «реакций-настроений» (например, не только лайк, а «согласен/спорно/весело»).

Задачи со звёздочкой
Сохранение состояния фильтров в localStorage.

WebSocket-обновление счётчика реакций в реальном времени.








Требования к содержанию презентации
Использованный стек;

Состав команды и роли;

Концепция мини-приложения и реализованный геймплей взаимодействия;

Скриншоты интерфейса;

Референсы (паблики VK, мини-аппы);

QR-коды на страницу с игрой/приложением и на кодовую базу.

Критерии оценки
Наличие рабочего прототипа;

Завершённость ленты и фильтров;

Выполнение цели — пользователь понимает, как работает сообщество;

Качество тестирования;

Качество презентации.
